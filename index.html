☁️ Game server — Supabase

        
One row in the quiz_rooms table is the whole game: room code, players, Ready states, question, scores, winner and the screen designs. Every screen reads that row once when it opens, then just listens — changes arrive live over the socket. Player taps (join, name, Ready, answer) are written straight into the same row by the player, and the Host adopts them from it. When nobody is doing anything, no screen calls the server at all.

About

        
Myth or Fact — 2 players · 10 random statements per round · fastest correct tap scores.

        
Build v49 · 28 Nov 2026 — one room row in Supabase is the whole game: connection, names, scores, questions, answers and the winner all travel in that one row. Screens read it once when they open, then follow it live. Nothing runs in the background. Connecting is allowed minutes, not seconds: no screen calls the server “not answering” until a call has gone unanswered for a full 3 minutes, and a room save that timed out is checked against the row itself before it is ever called failed.
